# Что исправлено в этой версии

Ниже — список изменений по файлам. Порядок совпадает с чек-листом задач.

## 1. `lib/screens/notes_screen.dart` — заметки

- Все обращения к полям записи сделаны null-safe (`note['title']`, `note['content']`,
  `note['category']`, `note['color']`): раньше при пустом значении в базе
  приложение падало на сборке карточки и на `Color(note['color'])`.
- Сохранена поддержка фото (`photo_path`), добавлена проверка существования файла.
- Убрано вложенное `setState` в `_filterNotes` (поиск пересчитывается локально).
- Если сохранённой категории нет в списке — она добавляется в выпадающий список,
  чтобы `DropdownButtonFormField` не падал с «value not in items».
- Вставка/обновление идут в отдельные ветки, без `id` в UPDATE.

## 2. `lib/screens/settings_screen.dart` — настройки

- **ID семьи полностью убран** (и экран, и использование `FamilyManager`).
- Файл `lib/utils/family_manager.dart` удалён — он был единственным местом,
  где генерировался/хранился `current_family_id`, и нигде не использовался.
- Темы/шрифт сохраняются в `SharedPreferences` (через колбэки в `main.dart`).
- Управление категориями: создание, переименование, удаление.
  При **переименовании** категория обновляется также в делах, покупках и заметках —
  раньше записи оставались со старым названием и «теряли» категорию.
- Удаление категории запрещено, если к ней привязаны дела/покупки (с числами в сообщении),
  и спрашивает подтверждение.

## 3. `lib/screens/purchases_screen.dart` — покупки

Открытие покупки (**тап по строке**) не работало по двум причинам, обе устранены:

1. `add_edit_screen.dart` обращался к `item.dueDate`, `item.dueTime`, `item.readingValue`
   у объекта `Purchase`, у которого таких полей нет → `NoSuchMethodError`
   сразу при открытии экрана. Теперь экран разбирает `Task` и `Purchase` по типу.
2. При сохранении в таблицу `purchases` уходила карта со колонками из `tasks`
   (`due_date`, `due_time`, `reading_value`) → `SQLiteException: no such column`.
   Теперь для покупок собирается только «своя» карта.

Дополнительно:

- Чекбокс обновляет только `isCompleted` (раньше в UPDATE уходил `id`).
- «Очистить выполненные» спрашивает подтверждение и показывает количество.
- Обновление списка жестом (pull-to-refresh), аккуратные подписи периодичности.

## 4. `lib/screens/family_screen.dart` — семья и возраст

- **Расчёт возраста** реализован корректно: учитывается, наступил ли день рождения
  в этом году, поддерживаются дети до года («8 месяцев», «12 дней»),
  правильные падежи («1 год», «3 года», «5 лет»).
- Дата рождения понимается в обоих форматах: `ДД-ММ-ГГГГ` (как пишет приложение)
  и `ГГГГ-ММ-ДД`; «31 февраля» и мусор отбрасываются.
- На карточке: дата рождения, возраст, ближайший ДР («через 12 дней»).
- В профиле (шторка) — фото/инициал, ФИО, родство, дата, возраст, ближайший ДР,
  переход в Wishlist, редактирование.
- Разбор ФИО стал устойчивым: «Иван» (одно слово) больше не превращается в фамилию,
  девичья фамилия в скобках вытаскивается обратно в отдельное поле.
- При удалении члена семьи удаляется и связанная запись из `birthdays`,
  если на неё больше никто не ссылается (иначе в «Днях рождения» оставался дубль).

## 5. `lib/models/gift.dart` + `lib/screens/gifts_screen.dart` — Wishlist

Причина, по которой желания не сохранялись:

- `Gift.toMap()` всегда включал `'id': id`. При **обновлении** существующего желания
  в базу уходило `id = NULL`, а в `INTEGER PRIMARY KEY` писать NULL нельзя →
  `SQLiteException`.
  Теперь `toMap({bool includeId = false})` по умолчанию **не** содержит `id`.

Также исправлено:

- При редактировании больше не теряется `reserved_by` (бронь другого члена семьи).
- Один чекбокс «куплено» (раньше в некоторых случаях рисовалось два).
- Ссылка открывается в внешнем приложении, с обработкой ошибки.
- Обновление списка pull-to-refresh, корректные аватары и заголовки групп.

## 6. `lib/db/database_helper.dart` — база данных

- **Версия схемы 14**, все таблицы создаются сразу в финальном виде
  (`CREATE TABLE IF NOT EXISTS`), включая `gifts.note/photo_path/reserved_by`,
  `tasks.due_date/due_time/reading_value`, `purchases.note`,
  `notes.category/photo_path` (в `onCreate` они тоже есть — раньше отсутствовали).
- `onUpgrade` больше не «лестница версий» с молчаливыми `try/catch`:
  добавлен хелпер `_ensureColumn`, который проверяет наличие колонки через
  `PRAGMA table_info` и добавляет только отсутствующие. База сходится к правильной
  схеме из любого состояния (в том числе если прошлые миграции упали).
- `PRAGMA foreign_keys = ON` (иначе `ON DELETE CASCADE` у показаний счётчиков
  не работал — при удалении дела оставались висячие строки).
- Индексы по `meter_readings.task_id`, `tasks.due_date`, `gifts.forWhom`.
- Базовые категории создаются и при создании, и при апгрейде.

## 7. Прочие файлы (без них исправления выше не работали)

### `lib/screens/add_edit_screen.dart` — переписан

- Типобезопасная работа с `Task`/`Purchase` вместо `dynamic`-обращений — это и есть
  «починка открытия покупок».
- Разные карты данных для `tasks` и `purchases` — устранён `SQLiteException`.
- `isCompleted` передаётся явно при вставке (в старых базах у колонки нет `DEFAULT`).
- Показания счётчика: новая точка добавляется только если значение изменилось.
- Напоминание ставится только на будущее время; для счётчиков — за N дней до подачи.

### `lib/main.dart` + `pubspec.yaml` — локализация

- Добавлены `flutter_localizations`, `GlobalMaterialLocalizations` и `supportedLocales`.
  Без этого `showDatePicker(locale: Locale('ru','RU'))` в «Днях рождения» падал
  с ошибкой отсутствующих `MaterialLocalizations`.
- Тема и размер шрифта применяются корректно, состояние загружается до первого кадра.

### `lib/utils/notification_service.dart`

- Убран параметр `uiLocalNotificationDateInterpretation` (в 17.x его нет — иначе
  ошибка компиляции).
- Исправлена **таймзона**: `timezone` по умолчанию ставит UTC, из-за чего
  напоминания приходили со сдвигом на часовой пояс. Теперь подбирается зона
  с текущим смещением устройства.
- Если нет разрешения на точные будильники (Android 12+) — откат на неточное
  уведомление вместо исключения.
- Удалён дубликат `lib/notification_service.dart` (мёртвая копия).

### `lib/screens/dashboard_screen.dart`

- Быстрое действие «Заметка» открывало вкладку **Семья** (индекс 3 вместо 4) — исправлено.
- «Ближайшие праздники» теперь реально ближайшие: даты парсятся и сортируются
  по количеству дней до ДР (раньше — строковое сравнение `ДД-ММ-ГГГГ`, то есть по дню месяца).
- «Дела на сегодня» учитывают ежедневные дела, чекбокс отмечает выполнение.
- Список обновляется pull-to-refresh.

### `lib/screens/meter_stats_screen.dart`

- Убран потенциальный крах `split('T')[1].substring(0, 5)` на записях без времени.
- Безопасный разбор числа показаний (строка/дробное с запятой).

### `.github/workflows/build-apk.yml`

- Добавлен шаг **core library desugaring** для `flutter_local_notifications` 17.x.
  Без него `flutter build apk` падает с ошибкой
  «Dependency ':flutter_local_notifications' requires core library desugaring to be enabled»
  (шаг правит `android/app/build.gradle` после `flutter create`, поддерживает и Kotlin DSL).
- Добавлен неблокирующий `flutter analyze` для диагностики в логах CI.

## Как проверить

1. Скопировать файлы в свой репозиторий и запушить в `main`.
2. GitHub Actions соберёт APK; он появится в разделе Actions → артефакт `family-lists-apk`.
3. Сценарии для ручной проверки:
   - Покупки → тап по позиции → изменить и сохранить; добавить новую и отметить выполненной.
   - Семья → добавить члена семьи с датой рождения → на карточке виден возраст.
   - Семья → Wishlist → добавить желание → открыть его и изменить → сохранить.
   - Заметки → создать заметку с фото и категорией, найти через поиск.
   - Настройки → переименовать категорию (дела/покупки должны сохранить привязку).

## Известные ограничения (не входит в эту правку)

- Фото из `image_picker` лежат во временной папке кэша — Android может их удалить.
  Для надёжности стоит добавить `path_provider` и копировать файлы в
  `getApplicationDocumentsDirectory()`.
- Уведомления о днях рождения пока не планируются (только о делах и счётчиках).
- Облачной синхронизации между устройствами нет — только локальная база.
